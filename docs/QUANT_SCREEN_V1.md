# Quant Screen V1 — mass discovery with a small, auditable trial universe

**Scope: Development only, illustrative research; no independent edge, HFT fill or arbitrage claim.** This adds offline analysis to an existing single-month C1+C2 feature ZIP. It does **not** authorize any new source read. It does **not** access 2025 Validation or 2026 Final OOS, GitHub secrets, Drive mounts, or source credentials.

## Research procedure

1. Use a **fresh** Colab 02 (research runtime), no Drive mount. Upload an existing private `HYPOLAB_DEV_*.zip` from the computer. The existing bundle loader verifies month, UTC, full SHA-256, every row/schema and C2_UNKNOWN semantics. Run the original descriptive preview if needed.
2. Build a **deterministic fixed default plan** with **1,440** variants (2 directional hypotheses × 6 imbalance thresholds × 6 holding horizons × 5 causal context regimes × 4 fixed UTC windows). All thresholds, metrics, minimum counts, UTC rules and null simulations are part of versioned code. Save and **download plan JSON before running the study**. This local registration is **not** an independently anchored preregistration, particularly after prior inspection of the month's outcomes.
3. Run **all** trials. The screen requires a complete Development calendar month except the final unavailable minute. It refuses partial, corrupt, protected or mismatched input, as well as modified/shortened plans.
4. Causal features: C1 close and C2 taker imbalance refer to the completed source minute. Trend uses the past 15 completed closes; relative-volatility classification uses the trailing 15 versus 60 minute *past* returns. No future-day normalization or target-aware feature construction. The signal is available only after the explicitly assumed feature-latency overlay.
5. For an event at minute `t`, the non-executable **entry proxy** is the next completed bar close (`t+1`), which must occur strictly after assumed feature availability. The **exit proxy** is the `t+1+horizon` completed bar close. **No entry at the signal minute close**; the close proxy itself is **not guaranteed executable at that price**. Both label closes must fall within the same UTC calendar day as the feature. Per-trial earliest-event greedy subsampling excludes overlapping horizons; no random IID trades assumption.
6. First **21 UTC calendar days** are TRAIN selection *within Development*; the remaining UTC days are **later Development diagnostic**, not Validation. The latter is never used for ranking. Eligibility requires >=50 training events across >=12 days, and diagnostic sufficiency requires >=15 events across >=5 days. All other variants remain in the report as INSUFFICIENT rather than silently dropped.
7. Report signed direction-follow/fade price returns (bps), positive fraction, event count, active days, and hypothetical round-trip **2/5/10 bps** total-cost net scenarios. No bid/ask spread, slippage, queue priority, exchange fees, funding, latency or capacity are observed in the ZIP. Unconditional long/short close-to-close proxies are supplied per horizon as **descriptive** benchmarks.
8. The conservative TRAIN multiple-comparisons screen uses **1024 common daily sign-flip draws**, fixed seed and the maximum positive daily t-statistic over all sufficient trials (maxT family-wise adjusted p). It assumes daily block-level exchangeability and null symmetry; residual dependence, nonstationarity and variable transaction costs can invalidate this inference. It is a **screen**, not a formal certainty claim. For top ten candidates, rank by TRAIN adjusted p then TRAIN 2-bps proxy only; never select on later Development diagnostics.
9. Download and retain both private plan and **complete** private JSON report (all 1,440 rows, negative/null/insufficient outcomes included). Do not commit generated files or results to GitHub. The JSON binds the exact bundle and plan SHA-256. An isolated local notebook is not an independent immutable audit archive.

## Acceptance and honest limits

- Synthetic tests cover full grid, refusal of altered plans, protected dates, partial-month sources, next-close / latency and day-boundary causality, nonoverlapping sampling, costs and missing status. CI runs Python 3.11 + 3.13; local NumPy is the only additional numerical dependency. Production input is still bounded by the ZIP loader and a single Development month.
- Screening **one** month cannot reliably reveal stable market regimes. No claim of effective sample size equal to 1m event count: outcomes overlap before subsampling and remaining daily blocks may still be dependent. One-month design, threshold grid and existing manual preview are exploratory exposures and cannot be converted into clean OOS by renaming them.
- To progress, ingest other independently permitted Development months (never 2025/OOS), preserve an externally anchored trial register and all null results, stress latency and actual executable maker/taker fill assumptions, then perform time-ordered selection and embargo/purging. Require separately approved Validation release before any genuine confirmation. HFT arbitrage would need venue-level order-book messages, synchronized cross-venue quotes, real fees/funding and execution/latency evidence **not supplied by C1+C2 1m bundles**.
